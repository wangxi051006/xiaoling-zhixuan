# 工程约定（校零智选融合版）

- 业务后端只使用 Go + MySQL InnoDB；Node 只用于前端构建，不承载订单/库存/支付权威数据。
- 金额使用整数分，禁止浮点元参与存储/比较/结算；订单、库存、支付状态分离。
- 任何建单/支付/退款/派单写操作必须走明确应用服务与事务；禁止通用 PATCH 直接改状态。
- 同一 requestId 同参重放、异参 409；库存不足整单回滚；禁止客户端自授角色或伪造已付/已送达。
- 取消/关单遇到支付 UNKNOWN/NOTFOUND 时，不得推定未付并释放库存；保留预留并进入核实/告警。
- 退款资金与实物回库分离；送达必须通过服务端配送点定位校验，并在事务内写入用户通知；不再使用用户签收码；旧配送员在改派后失去操作权。
- 不提交真实商户私钥、APIv3 Key、证书私钥、JWT 生产密钥、验证码/签收码明文或完整个人地址日志。
- 前端不展示虚构数字：报表来自 MySQL 聚合；演示数据必须 `is_demo` 标识；无数据显示空态。
- 修改后必须实际运行 `go test ./...`、`npm run build`（或在明确受限环境中如实记录未运行原因），不得编造通过。
