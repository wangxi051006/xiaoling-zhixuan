## 在 VS Code 中运行

1. 打开整个 `校零智选_最新版_20261114` 文件夹，或打开 `校零智选.code-workspace`。首次安装前端依赖时，在工程根目录依次运行：

~~~powershell
.\01_商家端\scripts\frontend.ps1 -Action Install
.\02_用户端\scripts\frontend.ps1 -Action Install
.\03_骑手端\scripts\frontend.ps1 -Action Install
~~~

2. 需要 Go 1.22+、Node 20.19+ 和可用 MySQL。`04_共用后端/.env.local` 读取本机数据库配置，不应提交或转发。新环境从 `04_共用后端/.env.example` 复制并填写自己的配置。
3. 本次新增 `0008–0012` 迁移，完整迁移目录为 `0001–0012`。本机数据库已有升级前备份；升级使用迁移，不重新 seed，也不重置原账号密码。需要手动应用迁移时，在确认数据库配置与备份后运行：

~~~powershell
.\04_共用后端\scripts\backend.ps1 -Action Migrate
~~~

4. 查看服务状态；尚未运行时再启动，然后检查三端代理及数据库版本：

~~~powershell
.\scripts\服务管理.ps1 -Action Status
.\scripts\服务管理.ps1 -Action Start
.\scripts\检查互通.ps1
~~~

`检查互通.ps1` 现在要求 `schemaVersion=0012_courier_capacity_recovery.sql`，并读取商品接口。检查成功代表代理与接口可用，不代表全部交易流程已完成验收。数据库实际迁移结果及后续 HTTP 验收以 [验收记录.md](验收记录.md) 为准。

修改 Go 后端后，需要重新编译启动才能生效。服务由本工程脚本管理时，可只重启后端，保留三端前端进程：

~~~powershell
.\scripts\服务管理.ps1 -Action RestartBackend
.\scripts\检查互通.ps1
.\scripts\检查三端登录.ps1
~~~

该操作核验已登记进程的 PID 和启动时间，不会自动停止其他工程的服务；旧日志保留，重启日志另存为 `.run/backend-0-restart-*`。未登记的 VS Code 手动后端，应在对应终端按 Ctrl+C 后重新运行启动命令。

5. 用上表账号打开对应网页。首次测试定位送达前，先在商家侧“配送点设置”填写真实校园 WGS84 坐标、所属楼栋和交付点名称。未配置配送点的历史订单需要先核对订单的配送点快照。
6. 结束测试时运行：

~~~powershell
.\scripts\服务管理.ps1 -Action Stop
~~~

服务管理仅处理本工程登记的进程。端口占用时先核对原服务，不自动更换端口或把未知进程作为本工程服务。若当前服务已经运行，直接打开网址即可。

各前端可在自身文件夹运行 `scripts/frontend.ps1 -Action Start`；后端可在 `04_共用后端` 运行 `scripts/backend.ps1 -Action Start`。前台运行按 Ctrl+C 停止。仅当 PowerShell 报禁止运行脚本时，可使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File 脚本路径 -Action 动作`，无需修改永久系统策略。
